# 设计语言与操作模型（源自 Multica 拆解）

> 目的：这是 AgentDeck UI 的"宪法"——所有界面改动对照本文执行，不再凭感觉贴皮。
> 来源：multica 源码（packages/ui、packages/views 布局组件的实现与注释）+ 官方文档站 42 页（即用户操作手册）。

## 一、设计语言（Layout Grammar）

### 1.1 表面分层（空间的语义）

四层底色，每层有明确身份，不许混用：

| 层 | 身份 | Multica 令牌 | AgentDeck 变量 |
|---|---|---|---|
| 壳 | 最安静的外框，包住一切 | `--app-shell` | `--app-shell` |
| 画布 | 内容生活的地方（列表/看板/对话） | `--page-canvas` | `--bg` |
| 表面 | 有边界的内容组（卡片/输入框） | `--surface` | `--bg-raised` |
| 浮起 | 临时浮层（菜单/对话框/toast） | `--surface-raised` | 浮层组件直接用 `--bg-raised` + 浮起阴影 |

**双阴影规则**：菜单/下拉用轻的 `--menu-shadow`；对话框/toast 用重的 `--shadow-pop`（floating-shadow）。浮层高度感靠阴影区分，不靠边框加粗。

### 1.2 页面骨架（每个页面都长这样）

```
┌ PageHeader（h-12，border-b，PAGE_GUTTER）─────────────┐
│ 图标 标题 计数 描述……              [操作钮][操作钮] │
├ Toolbar（h-12，同一 PAGE_GUTTER，与头部同檐）─────────┤
│ 搜索/过滤/排序……                   视图切换/显示选项 │
├──────────────────────────────────────────────────────┤
│ 内容区（滚动）                                        │
└──────────────────────────────────────────────────────┘
```

**铁律**（来自 multica 源码注释，每条都是踩坑教训）：
1. `PAGE_GUTTER` 是全局唯一常量——头部、工具栏、正文行共用同一条左边缘。"一个页面自己拼写沟槽，就是 bug 重演"。
2. 头部 + 工具栏**同高同檐**，读作一个 chrome 块；工具栏不是第二个头。
3. 把操作推到右边用内容组的 `flex-1`，**不用 `justify-between`**——否则标题被推到中间悬着。
4. 集合页头部公式：`图标(4×4, muted) → 标题(body, medium, truncate) → 计数(mono, tabular-nums, muted) → 描述(caption, muted) → 右侧操作`。
5. 空状态：居中，圆底大图标（12×12 圆），标题 + `max-w-md` 描述 + 动作行。

### 1.3 详情页骨架（签名布局）

```
┌ 头条（h-12，border-b，PAGE_GUTTER，含返回/面包屑）────┐
├───────────────────────────┬──────────────────────────┤
│ 主列（flex-1，滚动）        │ 属性栏（w-80，border-l， │
│ max-w-4xl 居中            │ p-4，行式：              │
│ 标题 → 描述 → 活动时间线    │ label(muted 小字) + 控件 │
│ → 评论输入                 │ 按 hr 分组；执行日志；    │
│                           │ 用量                     │
└───────────────────────────┴──────────────────────────┘
```

- 属性行：`小标签（muted，定宽）+ 控件`，分组间以细分隔线隔开；窄屏时属性栏收进抽屉。
- 主列 `max-w-4xl` 居中——阅读长度受控，不留白满屏。
- 骨架屏也必须遵守同一沟槽（加载时列不横跳）。

### 1.4 排印与质感

- **字阶只有六步**（角色命名）：micro 11 / caption 12 / label 13 / body 14 / title-sm 16 / title 18。"两个差 1px 的字号读作'一样但不对'"。
- 正文 14px 是主力；列表标题用 label(13)+medium；一切辅助信息 caption/micro + muted。
- 圆角基准 `--radius: 10px` 的倍率制；交互反馈 0.12s ease 过渡；焦点用 `ring`（外发光 3px），不用边框变色。

### 1.5 操作手感（交互模型）

- **触发要可预期**：凡是会唤醒 agent 的输入框，下方显示"触发预览"（谁会被唤醒）；不想触发任何人用 `/note`。
- **高风险动作有确认垫**：指派 agent 弹确认对话框（显示将启动谁 + 可选交接备注 + "暂不启动"）。
- **进度回到触发地**：在哪触发就在哪流式显示；执行日志可停/可重试。
- **键盘优先**：Ctrl+K 全局搜索、每页有快捷键（新建 C）、菜单 ↑↓ Enter Esc。
- 反馈用 toast，破坏性操作用确认框，永不用浏览器原生弹窗。

## 二、操作模型（用户手册摘要——用户的一天）

1. **建工作**：一句糙话 → Create with agent（AI 结构化成 issue）；或手动建档。
2. **派工作**（四种触发，共享权限规则）：
   - **指派 issue**（端到端拥有）：Assignee → 选 agent/squad → 确认框（预览将启动谁）→ 加交接备注（本次生效的范围/顺序/重点）→ Start。backlog 里的 issue 指派不启动，移出去才启动。
   - **评论 @mention**（只处理这一条，不改负责人）：@ 后必须从建议列表选（纯文本 @ 不触发）；agent 收到即建 task。
   - **直接聊天**：不建档的快问快答，每条消息一个 run；可带项目上下文。
   - **Autopilot**：周期性工作定时触发。
3. **看进度**：进度流回触发地（issue 时间线/聊天窗）；issue 头部"X is working"徽标；执行日志看全量步骤、token、可停可重试。
4. **协作收束**：agent 干完把 issue 推到 in_review；人评（评论区讨论/resolve 线程）；PR 合并自动 done；人决定 done。
5. **通知**：人的一切通知进 Inbox（agent 无收件箱）；需要人行动的标 action_required。

**AgentDeck 对应**：我们的"issue"= 任务（对话即时间线），四种触发收敛为工作区一句话（=指派+chat 合体）+ 后续追问（=mention 续聊）。操作模型已同构；差距在**呈现层**——详情页没有属性栏、页面没有统一骨架。
