# Worktree 保留、回收与 Windows 占用

## 什么时候删除

任务结束不等于立即删除目录。托管 worktree 使用 `.agentdeck-worktrees/.metadata/` 的 owner、分支与 generation 记录判断归属，目录名称不代表当前使用者：旧目录可能已经被后续任务复用。

| 场景 | 处理 |
| --- | --- |
| 正常委派子单完成，或失败但改动已落盘、工作区干净 | 全文报告、可选总结与 Git 报告采集结束后释放本地后端会话，再尝试归池；每个进程、每个仓库最多保留 2 棵空闲树，供后续派单复用 |
| 复用池已满 | 按既有安全条件移除目录；尚待集成的工作分支保留，集成成功后处理 |
| 集成续聊 worktree | owner 任务仍在册且登记了该集成分支时保留，供继续执行并保护交付成果 |
| 取消、未提交改动、人工保留 | 保留现场；清扫不强删未保存内容，取消现场通过显式删除任务处理 |
| 显式删除任务 | 先释放任务会话，再尝试回收其仍拥有的 worktree；目录被复用后不会替旧任务删除新 owner 的工作区 |
| 手动清扫 | 默认回收年龄为 30 天；运行中任务及其父任务、Git 操作、活跃复用池、被保留成果与脏工作区不删除 |
| 启动清扫 | 无年龄等待地检查可回收遗留树；活进程或无法确认死亡的另一进程的池仍保留，无可靠归属证据的目录报告为失败而不猜测强删 |

集成结果在分支上保存。清扫不代替用户处置仍登记的集成成果，也不删除保留的集成分支。

## 为什么任务结束后仍被占用

ZCode 的模型回合结束后，其 `app-server` 进程可以继续存活用于续聊。在 Windows 上，该进程的工作目录句柄会阻止重命名或删除 worktree。任务终态与进程终态是两件事。

回收入口现在先释放绑定到该目录的终态本地会话。ZCode 使用 `detach` 断开本地进程，不发送 `session/close` 销毁可恢复会话；之后追问仍可按原 `sessionId` 恢复。队员总结和报告必须在释放、归池之前完成。

进程树清理等待 `taskkill` 结束以及子进程的 `close`（包括标准流关闭），不再仅凭 `exit` 就宣称句柄已释放；并发清理共享同一个结果，已经退出的进程不再按旧 PID 重杀。会话释放失败或超时会阻止归池/删除并记录原因，后续可以重试。

外部编辑器、终端、开发服务器等不是本应用的任务会话，仍可能独立占用目录。应用不会根据目录名猜测并杀死外部进程。

## 现有残留怎么处理

- 更新应用后退出并重新启动，让旧会话收口、启动清扫重新核验遗留树；同一仓库有多个应用实例时先退出不再使用的实例。
- 关闭工作目录位于该 worktree 的外部终端、编辑器或开发服务器，再重试清扫。
- 查看清扫结果和任务时间线中的原因：复用池、年龄窗口、未提交改动、所有权变化与真实文件占用不是同一种问题。
- 若手工删过部分文件或 Git 注册已经损坏，先核对分支和成果备份，再单独处理；不要对整棵 `.agentdeck-worktrees` 目录强制递归删除。

## 回归验证

`npm run smoke:worktree-sessions` 在临时仓库复现 Windows 工作目录锁，验证终态进程释放、同一 provider 会话恢复、租约内手动清扫、失败保留与并发重试、运行中任务保护、总结/报告/归池顺序及真实 Windows 子进程树清理。该专项已纳入 `npm run smoke:worktrees`。
