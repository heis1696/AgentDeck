# 桌面宠物（Desktop Pet）

> **界面细节以最终实现为准。** 本仓库当前不存在 `src/main/pet/` 与 `src/renderer/src/pet/`，本文按既定功能规格描述；其中**设置项名、`pet.json` 字段名、七态状态名**属于稳定契约，实现须与本文一致。

---

## 1. 功能简介

AgentDeck 内置一只**像素风格桌宠**，常驻在应用窗口之上，把"看板里正在发生什么"变成看得见的陪伴：

- **平台无关**：桌宠由渲染层自绘，不调用任何平台特有的宠物/贴纸接口；Windows、macOS、Linux 上行为一致。
- **LLM 驱动**：桌宠的台词、反应与自主行为由你配置的模型生成，而不是预置的固定脚本。喂给它的**系统提示词（persona）**决定它的性格与说话方式。
- **素材与行为皆可自定义**：换一套图片目录就是一个新宠物；改一份 `pet.json` 就能改变它的走速、动画节奏与状态转移。无需改代码。
- **有交互、也有自主行为**：可以点它、拖它、找它聊天；没人理它时，它会自己走动、发呆、睡觉。

桌宠是**锦上添花**的功能：关掉它，AgentDeck 的一切照常工作。

## 2. 开关与设置

所有配置集中在**设置面板的「桌宠」卡片**（与「外观」「执行」等卡片同级）。

| 设置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| **开关** | 布尔 | 关 | 是否显示桌宠。关闭后宠物窗口不创建，也不产生任何模型调用。 |
| **素材包** | 下拉选择 | 内置默认包 | 选择使用哪个素材包。候选项来自素材目录下的各个 `<packId>` 文件夹，显示名取 `pet.json` 中的名称。切换后立即生效，无需重启。 |
| **persona 系统提示词** | 多行文本 | 内置默认人设 | 桌宠的"人设"。它决定宠物的语气、口癖、知识范围与台词长度。支持宏（见下表），每次生成前先做宏替换再发送给模型。 |
| **自主间隔** | 数字（秒） | 60 | 无操作时，桌宠每隔多久自主决策一次（走动 / 发呆 / 睡觉 / 说一句话）。调大更安静，调小更活泼；设为 0 表示关闭自主行为。 |
| **模型预设** | 下拉选择 | 跟随当前预设 | 桌宠调用模型时使用的预设（与任务执行共用同一份预设列表）。想让它更便宜更快，就单独选一个小模型预设。 |

设置卡片还会展示**当前状态**一行：好感（含等级）、心情（含文案）、今日投喂次数与最近看板事件——这些是养成系统的读数，不可直接编辑（见 §3.1 与 §6）。

### persona 中可用的宏

宏写在 persona 系统提示词里，形如 `{macro_name}`，生成前会被替换为当前真实值：

| 宏 | 替换为 | 用途 |
|---|---|---|
| `{board_summary}` | 当前看板的一句话摘要（有多少任务、进行中/已完成/卡住的数量等） | 让宠物"知道"你在忙什么，台词能对上正在发生的事 |
| `{recent_event}` | 最近一次看板事件（如「任务「编译修复」刚完成」；尚无事件时为「暂无」） | 让台词跟上刚刚发生的事：任务开始/完成/失败都能接得住 |
| `{pack_name}` | 当前素材包的名称 | 让宠物能自称（"我是 xx"），或在换素材后保持人设自洽 |
| `{time_of_day}` | 当前时段（清晨 / 上午 / 下午 / 傍晚 / 深夜） | 支持"早安""这么晚还不睡"这类随时段变化的台词 |
| `{model}` | 本次调用实际使用的模型名 | 便于宠物自嘲或自我介绍，也方便排查"到底谁在说话" |

未识别的宏会原样保留，不会导致报错。

## 3. 交互

| 操作 | 表现 | 说明 |
|---|---|---|
| **单击** | 反应台词 | 触发一次即时反应，气泡里出现一句与该状态下相符的短台词。连续点击会切换不同的反应，不会重复同一句。单击同时累积好感与心情（见 §3.1）。 |
| **双击** | 聊天 | 打开与桌宠的对话输入框，进入多轮聊天；关闭后回到自主行为。聊天比单击涨更多好感。 |
| **按住拖拽** | 跟手移动 | 按住宠物拖动时，它进入 `dragged` 状态，四肢悬空。 |
| **拖拽后甩出** | 抛掷物理 | 松手时把拖拽速度交给宠物：它会沿该方向飞出、受重力下坠、落地后回到走动。快速甩动会飞得更远。抛掷会掉一点心情（好玩但它会委屈），不扣好感。 |
| **右键 → 投喂** | 吃东西 | 选一份小零食（小鱼干 / 薄荷饼干 / 草莓大福），宠物播放 `eat` 动画（素材包缺该态时退回 `happy`）并说一句零食台词；好感 +4、心情 +8。每天前 5 次全额生效，之后"吃撑了"：好感停涨、心情只加一半。 |
| **右键 → 尺寸** | 缩放 | 100% / 150% / 200% 三档：窗体、精灵与鼠标命中区同缩放，精灵脚底位置不动。选择持久化，重启保持。 |
| **静置无操作** | 自主行为 | 每隔「自主间隔」，宠物自己决定：**走动**（在屏幕底部附近左右移动）、**入睡**（停住并播放睡眠动画）、**发呆**（原地待机），或说一句话。 |
| **任务开始/完成/失败** | 即时反应 | 看板任务开始、完成、失败时，宠物当场播一段动画 + 说一句反应台词（走 LLM，失败或频繁事件时用本地台词兜底）。任务完成涨好感，失败掉心情。见 §6.2。 |
| **位置记忆** | 记住上次落脚点 | 宠物的水平位置与所在屏幕会被持久化；下次启动时回到同一处，而不是弹回默认角落。 |

拖拽或聊天过程中，自主行为暂停，避免"你正在拖它，它自己走开"。

### 3.1 养成：好感与心情

宠物有两个 0-100 的数值（持久化在 `pet.json`）：

- **好感**：只涨不跌（长期不互动时按自然日缓慢衰减，每天 -2）。单击 +1、聊天 +2、投喂 +4、任务完成 +3。好感分五档：陌生 → 点头之交 → 熟悉 → 亲近 → 挚友。
- **心情**：随事件涨落。单击 +2、聊天 +4、投喂 +8、任务完成 +10、任务失败 -6、被抛掷 -3。低落时更想睡觉，开心时更爱蹦跶。

**数值如何影响行为**：好感与心情会调制素材包 `pet.json` 里的 `next` 加权转移表（心情 ≤30 时"入睡"权重 ×3；心情 ≥70 时"开心"权重 ×2；好感 ≥80（挚友）时"走动"权重 ×1.5），也会影响兜底台词的动作倾向（低心情偏睡、高好感偏撒娇）。这只改变运行时权重，不修改素材包文件本身。

**时间感知问候**：每天第一次见到宠物时（亮窗/开启开关），它会按时段主动打招呼（早安 / 中午好 / 晚上好……），走 LLM 生成、失败退回本地分时段台词；同一天内不会重复。

## 4. 素材包与行为格式规范

### 4.1 目录结构

一个素材包就是**一个文件夹**，放在（userData 即 Electron 的 `app.getPath('userData')`，Windows 下为 `%APPDATA%/agentdeck[-dev]`）：

```
<pets>/<packId>/       # 用户包：userData 下的 pets/ 子目录，运行时扫描，即放即用
```

内置包（当前只有 `default`）是构建时经 vite 内联进主进程 bundle 的（见 `src/main/pet/packs.ts`），不受运行时扫描影响——想让新包成为"内置"需要改代码并重新构建，普通使用走 userData 即可。

`<packId>` 即文件夹名（同时也是设置面板「素材包」下拉项的取值）。包内至少包含一份 `pet.json`，以及它引用的所有图片帧：

```
<pets>/<packId>/
├── pet.json          # 行为与素材描述（必需）
└── idle_0.png        # 图片帧（文件名由 pet.json 的 frames 决定）
└── ...
```

在 `pets/` 下新增一个文件夹并重开设置面板（素材包列表随状态快照实时扫描），下拉里就会出现新的选项；坏包会被跳过并在列表中标注。

### 4.2 `pet.json` 字段说明

```json
{
  "frameSize": [64, 64],
  "states": {
    "idle":   { "frames": ["idle_0.png", "idle_1.png"], "fps": 6, "loop": true, "afterSec": 6,
                "next": [{ "to": "walk", "weight": 3 }, { "to": "sleep", "weight": 1 }] },
    "walk":   { "frames": ["walk_0.png", "walk_1.png"], "fps": 10, "loop": true, "next": [] },
    "fall":   { "frames": ["fall_0.png"], "fps": 8, "loop": true, "next": [] },
    "dragged":{ "frames": ["dragged_0.png"], "fps": 8, "loop": true, "next": [] },
    "sleep":  { "frames": ["sleep_0.png", "sleep_1.png"], "fps": 2, "loop": true, "next": [] },
    "happy":  { "frames": ["happy_0.png"], "fps": 12, "loop": false, "next": [] },
    "think":  { "frames": ["think_0.png", "think_1.png"], "fps": 6, "loop": true, "next": [] }
  },
  "movement": { "walkSpeedPx": 40, "gravity": 1200, "edgeBehavior": "turn" },
  "bubble": { "offset": [0, -56] }
}
```

> 帧尺寸建议做 **64×64 正方形**：内置渲染舞台按 64px 精灵开孔，非 64×64 的帧会被等比缩放塞进 64px 方框（配合 §3 的尺寸档位整体放大）。上面的样例经 `validatePetManifest` 实测通过，可直接抄。

| 字段 | 类型 | 说明 |
|---|---|---|
| `frameSize` | 数字二元组 | 单帧尺寸 `[宽, 高]`（像素），如 `[64, 64]`。同一包内所有帧应保持一致。 |
| `states` | 对象 | 状态表，键为**状态名**，值为该状态的定义。七态必需；`eat` 为可选扩展态（见 4.3）。 |
| `states.<id>.frames` | 字符串数组 | 该状态的图片帧**文件名**，按顺序播放。单帧也行（数组只写一个）。 |
| `states.<id>.fps` | 数字 | 帧率：每秒播放几帧。越大动得越快，与移动速度无关。 |
| `states.<id>.loop` | 布尔 | 是否循环播放。`false` 表示播完最后一帧就停在末帧（适合一次性的高兴、惊讶）。 |
| `states.<id>.afterSec` | 数字（可选） | 循环态的自主转移秒数：播满该时长后按 `next` 加权挑下一个状态。省略时用包内默认节律。 |
| `states.<id>.next` | 数组 | **加权转移表**：本状态播放到该切换时，按权重随机挑选下一个状态。每项形如 `{ "to": "walk", "weight": 3 }`（注意键名是 `to` 不是 `state`）。空数组 `[]` 表示"不由动画自己决定去哪儿"（多用于 `walk` / `fall` / `dragged` 等由物理或交互驱动的状态）。 |
| `movement.walkSpeedPx` | 数字 | 走动速度，单位**像素/秒**。越大走得越快。 |
| `movement.gravity` | 数字 | 重力加速度，单位**像素/秒²**。被甩出或从边缘落下时决定下坠快慢，也决定抛掷手感。 |
| `movement.edgeBehavior` | 字符串 | 走到屏幕左/右边缘时的处理：目前支持转向（`"turn"`）。 |
| `bubble.offset` | 数字二元组 | 台词气泡相对精灵左上角的偏移量 `[x, y]`（像素，`y` 为负表示在宠物上方）。用来微调气泡位置，避免压住宠物的头。 |

**加权转移怎么算**：某个状态的 `next` 里各项权重相加为总权重，每项被选中的概率 = 自身权重 ÷ 总权重。上例 `idle` 的 `next` 总权重为 4，即 75% 概率转 `walk`、25% 概率转 `sleep`。各项权重全为 0 时视为不转移。

### 4.3 七态语义

桌宠的核心表现归结为这七个状态，状态名必须完全一致（大小写敏感），**缺失任何一个都算坏素材包**：

| 状态名 | 语义 | 何时进入 | 典型驱动 |
|---|---|---|---|
| `idle` | 待机 | 默认状态；无操作、无自主决策时 | 动画循环 + `next` 加权转移 |
| `walk` | 走动 | 自主行为选中"走动"，或落地后继续移动 | `movement.walkSpeedPx`，走到边缘按 `edgeBehavior` 处理 |
| `fall` | 下坠 | 被甩出后在空中、或从屏幕边缘落下 | `movement.gravity` |
| `dragged` | 被拖拽 | 按住拖拽期间 | 跟随鼠标，物理暂停 |
| `sleep` | 入睡 | 长时间无操作，自主行为选中"睡觉" | 低 `fps` 循环动画 |
| `happy` | 高兴 | 单击等正向交互的即时反应 | 一次性动画（`loop: false`），播完回到 `idle` |
| `think` | 思考 | 正在等模型返回、或双击进入聊天后的思考中 | 循环动画，出结果后切到 `happy` 或 `idle` |

**扩展态白名单**：除七态外，`pet.json` 还可以提供白名单内的可选状态——当前只有 **`eat`**（投喂动画，非 `loop`，播完回 `idle`）。扩展态**缺失不算坏包**（老素材包原样可用），只是对应交互退回近似表现：素材包没有 `eat` 时，投喂退回 `happy` 动画。白名单之外的自定义状态名会被校验拒收，防止脏数据混进状态机。

### 4.4 换素材：三步

1. 在 userData 的 `pets/` 下新建文件夹（Windows：`%APPDATA%/agentdeck[-dev]/pets/`），名字就是新的 `<packId>`（如 `pixel-dog`）。
2. 把图片帧拷进去，按帧写一份 `pet.json`：改 `name`、`frameSize`，并让每个状态的 `frames` 指向真实文件名。**七态建议全部提供**，缺失的状态会退回 `idle`。
3. 回到设置面板的「桌宠」卡片，在「素材包」里选中它。无需重启。

### 4.5 改行为：调 `next` 权重 / `fps` / 走速

- **想让它更爱走动**：把 `idle.next` 中 `walk` 的权重调大、其他项调小。例如原来 `walk:3, sleep:1`（75% 走动），改成 `walk:9, sleep:1`（90% 走动）。
- **想让它动得更快（画面节奏）**：调高该状态的 `fps`，例如 `walk` 的 `10` → `16`，脚步更利落。只改 `fps` 不会影响它移动多快。
- **想让它走得更快（位移速度）**：调 `movement.walkSpeedPx`，例如 `40` → `80`，横穿屏幕的时间减半。
- **想让它被甩得更"飘"或更"沉"**：调小 `movement.gravity` 更飘、滞空更久；调大则更沉、落地更快。
- **想让它睡前多犹豫一会儿**：把 `sleep` 的 `fps` 调低（如 `2` → `1`），呼吸般的慢动画更有困意。

## 5. 降级行为与静默模式

桌宠依赖模型才能"说话"，但**不能因为模型不可用就变成负担**。

### 5.1 未配置 API / 调用失败时

| 情况 | 桌宠的表现 |
|---|---|
| 没有可用的 API 配置 | 宠物**照常出现**并播放动画、走动、入睡——素材与物理完全本地，不需要网络。只是不说话。 |
| 调用失败（网络错误、超时、限流、余额不足、模型名无效） | 该次台词**静默丢弃**：不弹错误弹窗、不写入任务日志、不打断你手上的操作。宠物回到 `idle`，等待下一次机会。 |
| 连续失败 | 自动**退避**：降低自主说话频率，避免反复无效请求。恢复后自动回到正常节奏。 |
| 配置被修好 | 下一次自主决策或交互时自动恢复说话，无需重启。 |

要点：**桌宠的任何失败都不影响 AgentDeck 的核心功能**，也不会产生"错误"级别的提示。

### 5.2 静默模式

把「自主间隔」设为 `0` 即进入**静默模式**：宠物不再主动说话、不再自主走动，只保留动画待机与手动交互（单击/双击/拖拽）。适合演示、录屏或专注工作时使用。

相关约定：

- 每个会话对模型请求量有上限，达到上限后本次会话内不再自主说话（交互仍可用）。
- 静默模式与失败退避都不改变宠物的**位置记忆**与**素材包选择**。

## 6. 长期记忆与看板事件联动

### 6.1 长期记忆（「团子的记忆」）

聊天历史的环形上限是 20 条，滚出窗口的消息不会直接丢弃：它们进入一个待摘要队列，攒够 4 条后由模型压缩成一段第三人称记忆（不超过 300 字），与已有记忆合并（新段在前，总长 ≤800 字）持久化。之后每次生成台词（聊天、自主发言、事件反应、问候）都会把这段「团子的记忆」注入系统提示词，让宠物记得跨会话的事实——你提过的偏好、项目名、约定。

约定：

- 摘要走的是已配置的模型预设；**没有配置预设、调用失败或回复为空时静默跳过**，队列保留（上限 20 条，防无限膨胀），下次聊天后自动重试。
- 记忆只在本地 `pet.json`，不随任务/看板数据流转。

### 6.2 看板事件联动

桌宠订阅了任务状态流，**任务开始 / 完成 / 失败**时即时反应：播一段动画（开始→思考、完成→开心、失败→担忧）并说一句话，同时联动好感/心情（完成 +3 好感 +10 心情；失败 -6 心情；开始 +2 心情）。

- 台词优先走 LLM（能提到任务名），模型不可用或 **10 秒内已有事件反应**时退回本地台词组——批量跑任务时只有第一条走模型，不会刷屏也不会刷钱。
- 最近一次事件会记进 `{recent_event}` 宏与设置卡片，宠物在之后的自主发言里也能自然接话。
- 状态未变化的上报（runner 的高频重复通知）不触发反应。

## FAQ

**Q：宠物挡住我点按钮了？**
A：不会。宠物窗口只有宠物本体的像素区域接收鼠标；**透明区域不挡鼠标**，点击会穿透到下面的界面。如果确实觉得碍事，直接在设置里关掉「开关」。

**Q：Alt-Tab 切换窗口时看不到宠物？**
A：**这是预期行为。** 桌宠是一个常驻置顶的辅助窗口，被刻意排除在任务切换列表之外，也不显示在任务栏/Dock 上——它是"陪伴层"，不是你要切换的应用。关掉 AgentDeck 主窗口时宠物也随之退出。

**Q：重启后宠物跑到别的地方了？**
A：位置是持久化的，它会回到**上次的落脚点**。若你把显示器拔掉、或从多屏切到单屏，落在已不存在的屏幕上的坐标会被夹回主屏可视范围内，这是正常的容错。

**Q：换素材包后宠物变哑巴了？**
A：先检查该包的 `pet.json` 是否七态齐全、`frames` 里的文件名是否真实存在。缺状态会退回 `idle`，缺文件则该状态不显示。若只是不说话，见 §5.1——多半是模型配置问题，与素材包无关。

**Q：能同时养多只吗？**
A：当前规格为**单只**。想换风格请切换素材包。

**Q：宠物说的话会被记进任务历史吗？**
A：不会。桌宠的对话与任务、回合、事件日志相互独立，不会污染看板数据。

**Q：怎么投喂都不涨好感了？**
A：每天前 5 次投喂全额生效（好感 +4、心情 +8），之后团子"吃撑了"：好感停涨、心情只加一半，第二天恢复。设置卡片能看到今日已投喂次数。

**Q：它真的记得我之前说过的话吗？**
A：最近几轮靠聊天历史；更早的对话在滚出历史窗口后会被压缩成一段「团子的记忆」长期保存并注入后续对话（见 §6.1）。这段记忆依赖模型摘要——没配预设或摘要失败时会静默跳过，不影响使用。
